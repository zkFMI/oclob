# 実サービス接続画面の確認記録

## 対象と判定範囲

対象は、MPCとDeFMIの実際の公開記録を表示する読み取り専用画面です。
法人の認証、注文送信、在庫・資金の操作画面まで完成したという判定ではありません。
Product Designの監査手順に沿って既存画面を撮影し、実装後も同じ画面幅で確認します。
元のデモの色・書体・React Flow部品を使い、未実装の操作を模擬表示で補いません。

## 実装前に確認した問題

1. **表示するデータの経路が異なる。** 既存デモは同一プロセスの研究用状態を表示しており、別コンテナの常駐MPC・DeFMI経路を確認する画面ではありませんでした。説明自体は表示されていましたが、この画面を実ネットワークの検証結果として扱うことはできません。
2. **図の文字が小さい。** デスクトップでも、参加者・MPC・決済・台帳を一度に詰めた図では各処理を読み取りにくい状態でした。
3. **狭い画面で公開板が遠い。** 長い説明と模擬障害ボタンが先に並び、価格と数量を見るために大きくスクロールする必要がありました。

実装前の画面：

- [1440×1000](../artifacts/ui-native-20260906/01-before-desktop.jpg)
- [390×844](../artifacts/ui-native-20260906/02-before-narrow.jpg)

## 最初の実ネットワーク実行で確認したこと

Softbankの `/tmp/oclob-native.eWmizS` で、7台のMPCと5台のAvalanche検証ノードを動かしました。
結果は `artifacts/oclob_native_browser_rough_003.json` です。

- 売り注文の公開後、板が実際に更新番号1、2、3へ進みました。
- 75単位を2件に分けて同時決済した後、更新番号4で「価格100・残数量15」「価格101・残数量30」を確認しました。決済後の追加参加者署名は0件です。
- 同じ結果をデスクトップと390px幅のブラウザーで確認しました。
- 実際の配信コンテナを停止すると、価格行が消え、「公開板を確認できません」に変わりました。API応答を差し替えたテストではありません。
- 詳細の開閉と手動再取得が動作し、ブラウザーのエラー・警告記録はありませんでした。

この段階の画面は**合格にしませんでした**。次の問題を修正しました。

| 問題 | 原因 | 修正 |
|---|---|---|
| 図がMPC 1→MPC 2のような依存関係に見える | 配信先への線が隣のカードを横切る | カードの外側を通り、各署名が独立していると分かる線に変更 |
| 拡大・縮小ボタンの記号が見えない | 汎用ボタンの余白がReact Flowの操作部にも適用される | ヘッダーのボタンだけにスタイルを限定 |
| 指定したローカル転送ポートにつながらない | 内部ネットワークだけに属するコンテナで、Dockerがポートを公開しない | 公開情報だけを読むAPIに限り、追加の接続用ネットワークへ参加させる。公開先は引き続き127.0.0.1のみ |
| 回路で許可される9価格帯目を画面が拒否する | 既存8枠と到着注文1枠を区別せず上限8にした | 回路と同じ上限9へ修正し、境界の単体テストを追加 |

Dockerの構成は[公式のネットワーク構成例](https://docs.docker.com/engine/network/)に基づきます。
MPC・法人・台帳のコンテナを外部向けネットワークへ接続する変更はしていません。
最初の実行では、確認済みのコンテナIPへのSSH転送で画面検証を続けました。これは最終導入手順ではなく、修正後に文書どおりのポートを再検証するための一時診断です。

## 自動テストと最終確認

SoftbankでRustの129件、画面の入力検査・部品描画5件が成功しました。
画面本体・Vite設定・テスト設定の型チェックとビルドも成功しました。
画面部品の人工データは単体テスト専用であり、金融処理の検証には使っていません。

修正後の `/tmp/oclob-native.0NA16w` でも実際に2件・合計7,500の決済が成立し、4回の公開板取得、6種類のHTTP異常応答、実プロセス終了からの復旧、検証ノード再起動後の一致を確認しました。結果は `artifacts/oclob_native_http.json`、実行ソース165ファイルとの一致は `artifacts/oclob_native_browser_sources.json` に記録しています。

通常のSSH転送ポート19880で、更新番号4、売り価格100・残数量15、売り価格101・残数量30、署名7件、台帳の高さ16を表示しました。最終画像を保存後に開き直し、実装前の同じ画面幅の画像と比較しました。

- [修正後1440×1000](../artifacts/ui-native-20260906/08-native-final-desktop.jpg)：価格と図を同時に読み取れ、線が隣のカードを横切らず、操作記号が見えます。拡大操作で実際の図の倍率が変わり、全体表示へ戻ることも確認しました。
- [修正後390×844](../artifacts/ui-native-20260906/09-native-final-narrow.jpg)：価格と残数量を先に表示し、本文の幅も390pxで横にはみ出しません。
- [実行終了後の狭い画面](../artifacts/ui-native-20260906/10-native-final-network-unavailable-narrow.jpg)：配信元の終了後、価格行は0件となり、図も未確認の状態へ変わりました。拡大記号とカードは読めます。図全体は縦スクロールして閲覧します。

説明の開閉と手動更新も確認しました。最終ブラウザーのエラー・警告記録は空でした。停止時の確認は実サービス終了後の画面であり、HTTP応答の置き換えではありません。最初の実行では配信コンテナ単独の停止も確認しています。

**判定：今回の読み取り専用経路は、限定した実結合・画面確認を通過しました。** 本番受入ではありません。法人の認証、注文・資金操作、常設デモ、無取引時の公開板更新、独立運営者間のWAN試験は未完了です。試験終了時に今回のコンテナは通常どおり削除されるため、ポート19880は常設URLではありません。既存のポート18800のデモは変更していません。
